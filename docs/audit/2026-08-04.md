# Audit — 2026-08-04 (re-audit of the repaired v2.6.15 tree, scoping 2.7.0)

**Scope:** all 34 math modules in `src/` (~17,300 lines) at released tag `2.6.15`, plus the four
test suites, `tests/hisab.bcyr` and `scripts/check-constants.sh`. `lib/` (vendored) and `dist/`
(generated) were out of scope. Six dimensions: regression verification of the 2.6.12–2.6.15
repairs, a fresh numerical sweep, a fresh memory-safety sweep, test quality, refactor survey, and
performance/API consistency. Every finding was handed to an independent adversarial verifier
instructed to refute it, most of which compiled and ran probes against the real modules.

**Result: 42 findings confirmed, 8 refuted.** By severity: **4 high, 21 medium, 17 low** — no
criticals. By category: correctness 12, test-quality 12, memory-safety 5, performance 5,
api-consistency 4, refactor 2, docs 2.

This supersedes nothing. It **corrects** [`2026-08-03.md`](2026-08-03.md)'s disposition record —
see §2.

---

## 1. The repairs hold

**Regression verification came back clean: zero regressions.** This is the headline, and it was
established by execution rather than inspection — the four tableaux were decoded straight out of
`src/` with `struct.unpack` and checked against *mathematical invariants*, not against their
comments:

- **DOPRI45** — Σb = 1.0 exactly; every stage row Σa_ij = c_i to ≤ 6.7e-16; the order conditions
  Σb·cᵖ for p = 1..4 and Σb·A·c all correct; e_i = b5_i − b4_i for all seven. A single dt = 0.1
  step of y' = y lands 2.58e-10 from e^0.1 — genuine order-5 behaviour.
- **BDF-2/3/4/5** Σα = 1.0 exactly. **Yoshida-4** satisfies both 2w₁+w₀ = 1 and 2w₁³+w₀³ = 0.
  **Gauss-Legendre-5** is bit-exact with moments x⁰..x⁹ exact through its degree-9 bound.
- `svd_golub_kahan` reconstructs `A = U·S·Vᵀ` on non-symmetric, rectangular and rank-2 inputs with
  U and Vᵀ both orthogonal — **and re-running the same probe against the pre-2.6.13 file
  reproduces the old failure**, so the U-transpose fix demonstrably holds rather than being
  masked.
- `eigen_qr` converges for n = 2,3,4,5 (n = 4 and 5 have no in-tree coverage) with `A·v = λ·v` for
  every pair. The SU(2)→SO(3) square, `se3_log∘se3_exp`, `einsum`, the interval enclosures, the
  hull and half-edge rewrites (verified on a 65×65 grid — 4× the audit fixture, instant), and all
  the capped-constructor guards behave as specified.

The 2.6.15 performance rewrites were also verified *correct*, not merely fast: the hashed
half-edge pairing matches brute force exactly on a 128-triangle grid, and the hull heapsort
produces byte-identical output.

## 2. Correction: the 2026-08-03 audit was **not** fully discharged

The 2.6.15 CHANGELOG, roadmap and doc-health all recorded the 2026-08-03 audit as closed in full.
**That was wrong, and this re-audit found it.** Six of the original 70 findings were never fixed:

| Original finding | Status |
|---|---|
| `geo.cyr:458` `geo_ray_capsule` returns NaN on a parallel miss | still live |
| `complex.cyr:373` `cmat_exp` scaling loop never terminates on an infinite norm | still live |
| `geo.cyr:217` ray-section header states a miss contract `geo_ray_plane` does not implement | still live |
| `f64_util.cyr:19` `f64_fmod` uses floor where its own doc says trunc | still live |
| `f64_util.cyr:26` `f64_copysign` wrong for a negative-zero sign argument | still live |
| `lie.cyr:507` `lorentz_is_valid` absolute tolerance rejects valid boosts at high rapidity | still live |

**Root cause — a process failure, not an oversight in any one release.** The repair work was
scheduled from the roadmap's P0–P4 *summary bullets*, which were written as a deduplicated digest
of the 70 findings. Several MEDIUM and LOW items never appeared in those bullets, so they were
never scheduled, and "all P-tiers closed" was then read as "all findings closed". The two are not
the same thing, and nothing checked one against the other.

**Process fix, applied:** an audit's finding list is the unit of disposition, not the roadmap
digest derived from it. A future audit closes only when every numbered finding has an explicit
disposition — fixed, refuted, or consciously deferred with a reason.

## 3. The constant gate had a 25% blind spot

`scripts/check-constants.sh` — added in 2.6.12 precisely to make the mis-transcribed-constant
class mechanically impossible — printed a confident **"110/110 verified"** while silently
skipping **35 of 145** declarations. Its regex matched the payload as `[0-9A-Fa-f]{1,16}`, which
does not admit the `_` digit separators Cyrius accepts and which `src/` uses freely
(`0x4008_0000_0000_0000`).

**Fixed in this pass** (the gate is infrastructure, not a scheduled work item): the hex class now
accepts `_`, separators are stripped before decoding, and ±Infinity is verified explicitly rather
than skipped. Coverage went **110 → 145** constants, and the newly-visible set contained a real
defect: `symbolic_ext.cyr:213`'s `limit` encoded 9999999978962944.0 against a documented `1e15`
— corrected. Only `_COL_SENTINEL` is now skipped, and only because its comment is prose.

A gate that reports a count without reporting what it *skipped* is a gate that can rot silently.
It now prints the skip list.

## 4. Where the remaining findings concentrate

`geo_advanced.cyr` is the largest module in the library (1,261 lines) and the 2026-08-03 sweep
**did not cite it once**. Its GJK/EPA, BVH, SDF/CSG, swept-AABB and TOI sections have no test
coverage, and four findings land there — including `_bvh_build_rec` degenerating to a
1-vs-(n−1) split on coincident AABBs (the unfixed sibling of the `kdtree_build` defect fixed in
2.6.14) and `time_of_impact` silently missing every collision beyond 0.63 units of relative
travel because its advancement quantum is a fixed distance and `max_t` can only shrink the
horizon.

Twelve findings are **test-quality**: assertions that cannot fail for the right reason. The
worst are `num_rk4`'s single assertion tolerating a 90% error, `ode_verlet`/`ode_symplectic_euler`
asserted only `!= 0`, a "gell-mann hermitian" check that is a tautology, and 21 assertions using
`f64_from(1)` — a literal tolerance of **1.0** — on quantities whose exact value is 0 or 1.

## 6. What is clean

Recorded so the next audit does not re-plough it:

- **Raw integer comparisons on f64 bit patterns — none left.** A per-function taint scan plus a
  targeted grep over every relational operator applied to an f64-valued expression found no
